## 1. 目标与非目标

### 1.1 目标

- 前端运营看板能够调用后端真实接口（`/events`、`/events/{id}`、`/events/{id}/timeline`、`/metrics`、`/events/{id}/approval`），正确渲染数据。
- 解决跨域问题，使前端开发服务器（localhost:8080）能与后端（localhost:8000）正常通信。
- 修复前端点击事件导致右侧详情无法切换的 Bug。

### 1.2 非目标

- 不涉及后端业务逻辑修改。
- 不涉及前端 UI 重构或新增功能。
- 不涉及生产环境部署。

## 2. 职责与边界

- 本模块负责：前端页面与后端接口的对接、跨域配置、前端交互逻辑修复。
- 本模块不负责：后端接口的正确性、数据生成、审批流程的业务逻辑。
- 需要人工参与的环节：后端启动后需手动调用 `POST /runs` 生成测试数据（或在 Swagger 中执行）。

## 3. 输入与输出

### 3.1 输入

| 字段/对象 | 类型 | 必填 | 来源 | 含义与约束 |
|---|---|---|---|---|
| 后端 Base URL | string | 是 | 环境配置 | `http://127.0.0.1:8000` |
| 事件列表 | JSON Array | 是 | GET /events | 事件 ID、标题、状态等 |
| 事件详情 | JSON Object | 是 | GET /events/{id} | 告警、研判、调查、处置 |
| 时间线 | JSON Array | 是 | GET /events/{id}/timeline | 状态变更记录 |
| 指标 | JSON Object | 是 | GET /metrics | total_events 等 |
| 审批请求 | JSON Object | 是 | POST /events/{id}/approval | 审批意见、审批人 |

### 3.2 输出

| 字段/对象 | 类型 | 去向 | 含义与约束 |
|---|---|---|---|
| 页面渲染 | HTML/CSS/JS | 用户浏览器 | 展示事件列表、详情、时间线、指标 |
| 审批响应 | JSON | 前端回调 | 显示审批成功/失败消息 |

## 4. 核心流程与状态变化

1. 用户打开页面 → 前端调用 `GET /events` 获取事件列表 → 渲染左侧列表。
2. 用户点击某事件 → 前端调用 `GET /events/{id}` 和 `GET /events/{id}/timeline` → 渲染右侧详情和时间线。
3. 页面加载时自动调用 `GET /metrics` → 渲染顶部指标卡片。
4. 用户点击"审批"按钮 → 弹出审批弹窗 → 提交 `POST /events/{id}/approval` → 显示结果并刷新列表。

状态变化：事件状态（open → in_progress → resolved 等）由后端控制，前端仅展示。

## 6. 安全边界

- 权限与审批：前端仅展示审批按钮，后端负责鉴权（当前 MVP 无鉴权）。
- 输入校验：前端对审批表单进行非空校验，后端负责格式校验。
- 敏感信息处理：前端不存储敏感数据，展示时脱敏（IP、主机名等替换为 `***`）。
- 失败、超时与人工接管：后端不可用时前端自动降级为演示模式（Mock 数据）。
- 真实执行与Mock边界：联调时使用真实后端数据，Mock 数据仅用于演示模式。

## 7. 关键设计决策

| 决策 | 原因 | 未采用方案及原因 |
|---|---|---|
| 前端通过 `fetch` 直接调用后端 API | 简单直接，无需引入 Axios 等额外依赖 | 使用 jQuery.ajax 也可，但 fetch 更现代 |
| CORS 在后端配置（白名单方式） | 后端统一管理跨域策略，前端无需额外代理 | 前端代理（webpack-dev-server）会增加复杂度 |
| 前端增加 `if (element)` 保护性检查 | 避免因 DOM 元素不存在导致的 JS 报错 | 直接删除 `$("#cur-trace")` 引用，但会影响其他功能 |

# T0827-04 数据来源与降级设计

## 1. 数据来源标识设计
- **来源标签逻辑**：页面右上角新增“数据来源”标签。
  - 当后端返回数据中包含 `sample_nature` 字段时，显示“固定样例 / Mock 数据”。
  - 当无此字段或为真实数据时，显示“真实数据”。
  - 确保不将 Mock 数据冒充为真实 XDR 数据。

## 2. 降级边界设计 (demo-data.js)
- **触发条件**：仅在检测到后端服务完全不可用（如网络断开、连接超时、HTTP 5xx 错误）时触发。
- **正常联调**：只要后端能返回任何响应（即使是空数组），绝不静默使用 `demo-data.js`。
- **降级表现**：触发后，页面显示预设的演示数据，并在顶部显示明显的“已降级至演示模式”提示。

## 3. 异常处理设计
- **鉴权失败 (401/403)**：跳转至登录页或弹出提示。
- **空结果**：列表显示“暂无事件数据”占位图。
- **超时 (10s)**：自动触发上述降级逻辑。
- **Fallback**：局部组件（如卡片、图表）渲染失败时，显示兜底 UI，不影响页面整体。
