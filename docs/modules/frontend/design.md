# 前端模块设计说明

## 一、为什么这样设计

本模块为安全智能体系统提供运营看板的前端展示层。设计目标如下：

1. **最小可运行**：单页 HTML 应用，双击即可打开，无需构建工具或后端服务。
2. **接口先行**：前端字段命名严格对齐后端 `domain/models.py`（snake_case），接口路径对齐 `api/routes/`。
3. **演示降级**：后端不可用时自动回退到内嵌演示数据，确保展示不中断。
4. **状态可视化**：以 11 种 BusinessStatus 为状态机，用颜色语义化区分事件处理阶段。

## 二、模块组成

```
frontend/
├── index.html        # 单页入口（三段式布局）
├── app.js            # 数据层 + 渲染逻辑 + 审批交互
├── demo-data.js      # 人工构造的演示数据（Mock）
├── styles.css        # 深色后台样式
└── README.md         # 项目说明
```

### 页面布局（五区）

| 区域 | 位置 | 内容 |
|---|---|---|
| A 事件列表 | 左上 | 事件 ID、Trace ID、状态、来源、风险分、优先级、摘要 |
| B 告警关联 | 右上（详情区） | 关联告警数、实体列表、关联理由 |
| C 风险研判 | 右上（详情区） | 判定结论、置信度、风险分、优先级、证据缺口 |
| D 可审计时间线 | 右侧中部 | 调查步骤（step_no / goal / observation） |
| E 处置记录 | 右侧下部 | 处置计划、执行模式（suggest/mock/real）、验证状态 |
| F 关键指标 | 底部 | 总告警数、已闭环、平均响应时间、人工介入次数 |

## 三、输入输出

### 输入（接口基线）

| 接口 | 方法 | 用途 |
|---|---|---|
| `/events` | GET | 获取事件列表 |
| `/events/{event_id}` | GET | 获取事件详情 |
| `/events/{event_id}/timeline` | GET | 获取处理时间线 |
| `/events/{event_id}/approval` | POST | 提交审批决策 |
| `/metrics` | GET | 获取运营指标 |

### 输出

- 事件列表表格
- 事件详情面板（含告警关联、风险研判、时间线、处置记录）
- 审批弹窗（提交 approved / approver / reason / idempotency_key）
- 指标卡片（数字 + 趋势标注）

## 四、安全边界

1. 前端不存储任何敏感信息（Token、密码、内网地址）。
2. 演示数据为人工构造，不包含真实平台数据。
3. 审批弹窗的 `idempotency_key` 由前端 `crypto.randomUUID()` 生成，防止重复提交。
4. 接口不可达时自动降级，不暴露后端错误堆栈。
